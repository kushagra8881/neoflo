\begin{abstract}
Real-world enterprise document pipelines frequently encounter heterogeneous batches of scanned images and multi-page PDFs where multiple document types are intermixed without explicit separators. This technical report details the end-to-end design, implementation, and empirical evaluation of an autonomous, dataset-independent document understanding and semantic clustering system. The system addresses four difficult enterprise challenges: (1) isolating multiple distinct document cards on a single flatbed scan, (2) detecting document boundaries across arbitrary multi-page PDFs, (3) preserving multi-page document continuity, and (4) categorizing previously unseen document types in a zero-shot manner. Our hybrid pipeline combines fast digital PDF parsing (PyMuPDF), local edge-detection and Non-Maximum Suppression (OpenCV), local text extraction (RapidOCR / PaddleOCR PP-OCRv4), dense semantic embeddings (Sentence Transformers), unsupervised K-Means with automatic Silhouette score estimation, and structured reasoning with Google Gemini 3.8 Flash. Because no standardized public ground-truth dataset covers all four scenarios simultaneously, we engineered a dedicated synthetic evaluation benchmark database. The entire pipeline runs locally in under 15 seconds, achieves 100\% boundary precision/recall on multi-page transitions, and is deployed as an interactive Streamlit web application.
\end{abstract}

\section{Introduction and Problem Formulation}
% -------------------------------------------------------------
Standard document classification systems typically presuppose that each incoming file corresponds to exactly one pre-segmented document belonging to a fixed, pre-trained taxonomy. In real enterprise environments (e.g., banking, logistics, insurance, legal auditing), this assumption consistently fails:
\begin{enumerate}[leftmargin=*]
    \item \textbf{Scenario A (Multiple Documents on a Single Page):} Scanned images often contain multiple physical documents (e.g., an invoice, a cashier receipt, and an identity card) placed together on a single scanner bed. A naive full-page OCR creates contaminated, merged text representations that corrupt downstream classification.
    \item \textbf{Scenario B (Multiple Documents Throughout One PDF):} A single 100-page compound PDF might contain an invoice across pages 1--5, a customer KYC form on pages 6--8, another invoice on pages 9--15, and a bank statement on pages 16--20. The system must discover logical transitions autonomously.
    \item \textbf{Scenario C (One Document Spanning Multiple Pages):} Multi-page documents (e.g., 12-page bank statements or multi-page commercial contracts) must not be prematurely split into isolated single-page documents; their content must be unified before document-level clustering.
    \item \textbf{Scenario D (Previously Unseen Document Types):} The application must generalize to completely novel document categories (e.g., unfamiliar environmental audit reports or specialized medical dossiers) in an unsupervised, dataset-independent manner without requiring model retraining.
\end{enumerate}

To solve these problems without relying on expensive, cloud-dependent per-page LLM calls, we designed a hybrid architecture prioritizing local computer vision and transformer models for core extraction, reserving LLM reasoning strictly for cluster naming, semantic explanation, and ambiguous edge-case disambiguation.

\section{System Architecture and Implementation}
% -------------------------------------------------------------
The system follows a modular pipeline partitioned into six sequential phases:

\begin{figure}[h]
\centering
\begin{calloutbox}{Hybrid Document Processing Pipeline}
\textbf{Input Files} (PDF, PNG, JPG, TIFF) $\longrightarrow$ \textbf{Fast-Path PyMuPDF / RapidOCR} $\longrightarrow$ \textbf{Spatial Region Cropper (Scenario A)} $\longrightarrow$ \textbf{Multi-Signal Boundary Engine (Scenarios B \& C)} $\longrightarrow$ \textbf{Dense Sentence-Transformers ($E \in \mathbb{R}^{N \times 384}$)} $\longrightarrow$ \textbf{Unsupervised K-Means with Silhouette $K$-Selection} $\longrightarrow$ \textbf{Gemini 3.8 Flash Reasoning} $\longrightarrow$ \textbf{Interactive Streamlit UI}
\end{calloutbox}
\end{figure}

\subsection{Phase 1: Input Validation and Local OCR Extraction}
\begin{itemize}[leftmargin=*]
    \item \textbf{Hybrid Extraction Fast-Path:} Built with PyMuPDF (\texttt{fitz}). Digitally generated PDFs are parsed in $< 50\,$ms, extracting embedded text blocks and layout structures directly. Scanned documents or image-only pages are automatically routed to our local OCR engine.
    \item \textbf{Local OCR Engine:} Uses RapidOCR, executing PaddleOCR's latest PP-OCRv4 detection and recognition models via ONNX Runtime on CPU/CUDA. This eliminates external cloud OCR latency, avoids PyTorch C++ library conflicts, and achieves an average text line confidence of \textbf{0.948}.
    \item \textbf{Deterministic Cues Extraction:} Regular expressions extract invoice IDs (\texttt{INV-*}), bank account numbers (\texttt{ACCT-*}), pagination strings, and keyword flags.
\end{itemize}

\subsection{Phase 2: Document Segmentation and Boundary Detection}
This represents the core algorithmic contribution of our implementation.

\subsubsection{Single-Page Multi-Document Separation (Scenario A)}
To prevent text contamination when multiple documents occupy the same scanned page, \texttt{RegionDetector} executes:
\begin{enumerate}
    \item Grayscale conversion and bilateral smoothing.
    \item Canny edge detection ($T_{\text{low}}=30, T_{\text{high}}=100$) followed by rectangular morphological closing.
    \item External contour extraction, filtering for candidate document areas ($0.04 \le \text{Area} / \text{TotalArea} \le 0.96$) and aspect ratios ($0.15 \le w/h \le 6.0$).
    \item \textbf{Non-Maximum Suppression (NMS):} Suppresses nested inner borders using an Intersection-over-Union (IoU) threshold of 0.35 and containment ratio of 0.65.
    \item Each discovered crop is saved as an independent image and submitted to independent OCR extraction.
\end{enumerate}

\subsubsection{Multi-Page PDF Boundary Engine (Scenarios B and C)}
For a document of $N$ pages, we model the probability of a document boundary occurring between adjacent pages $i$ and $i+1$ using the following composite scoring equation:
\begin{equation}
B_i = w_s (1 - S_i) + w_h H_i + w_m M_i + w_v V_i
\end{equation}
where:
\begin{itemize}[leftmargin=*]
    \item $S_i = \mathbf{E}_i \cdot \mathbf{E}_{i+1}$ represents the cosine similarity between the normalized dense semantic embeddings of page $i$ and page $i+1$.
    \item $H_i \in [0, 1]$ represents the heading transition signal. $H_i = 1.0$ if page $i+1$ begins with an explicit document title (e.g., ``COMMERCIAL INVOICE'', ``STATEMENT OF ACCOUNT''); $H_i = 0.0$ if page $i$ ends with an explicit continuation footer (e.g., ``Continued on next page'').
    \item $M_i \in [-1, 1]$ represents the metadata mismatch signal. An invoice ID mismatch yields $M_i = 1.0$; matching account IDs yield $M_i = -0.5$; consecutive pagination (``Page 1 of 4'' $\to$ ``Page 2 of 4'') yields $M_i = -1.0$ (strongly inhibiting a split).
    \item $V_i \in [0, 1]$ represents visual layout and text-density divergence.
    \item The empirical weights are tuned to: $w_s = 0.40, w_h = 0.25, w_m = 0.25, w_v = 0.10$.
\end{itemize}
If $B_i \ge 0.52$, page $i+1$ is declared the starting boundary of a new logical document.

\subsection{Phase 3: Document-Level Semantic Embeddings}
For each assembled logical document (which may span 1 to 20+ pages), we generate a single normalized dense vector:
\begin{itemize}[leftmargin=*]
    \item Extracted text is normalized by removing repetitive page headers and formatting noise.
    \item For long documents, text is chunked into 180-word windows with 30-word overlap.
    \item Chunks are encoded via \texttt{sentence-transformers/all-MiniLM-L6-v2} into 384-dimensional embeddings.
    \item \textbf{Position-Weighted Aggregation:} To prioritize identifying information, the lead chunk (title and first page) is assigned a 40\% weight, while subsequent chunks share the remaining 60\%. The aggregate vector is $L_2$-normalized: $\|\mathbf{E}_{\text{doc}}\|_2 = 1.0$.
\end{itemize}

\subsection{Phase 4: Unsupervised Clustering and Automated $K$-Selection}
Document vectors $\mathbf{E} \in \mathbb{R}^{N \times 384}$ are clustered using K-Means:
\begin{itemize}[leftmargin=*]
    \item \textbf{Automatic $K$ Estimation:} Candidate values of $K \in [2, \min(8, N-1)]$ are evaluated using the Silhouette Score and Davies-Bouldin Index. The $K$ maximizing the Silhouette score is selected.
    \item \textbf{Ambiguity and Outlier Detection:} For each document $i$, we compute its Euclidean distance $d_1$ to its assigned centroid and $d_2$ to the second-nearest centroid. If the margin ratio $d_2 / d_1 < 1.18$ or $d_1 > 0.85$, the document is flagged as \textit{Ambiguous (Review Recommended)}.
    \item \textbf{2D PCA Projection:} Principal Component Analysis reduces the 384-D embeddings to $(x, y)$ coordinates for real-time scatter plot visualization.
\end{itemize}

\subsection{Phase 5: Gemini 3.8 Flash Semantic Reasoning}
Gemini 3.8 Flash is queried using structured JSON output schemas to convert mathematical clusters and raw text into readable business intelligence:
\begin{itemize}[leftmargin=*]
    \item \textbf{Cluster Labeling \& Explanation:} Generates short labels (e.g., ``Invoices \& Billing'', ``Regulatory Compliance'') and concise explanations.
    \item \textbf{Fine-Grained Document Type Classification:} Classifies individual documents into exact types (e.g., Commercial Invoice, Passport, POS Receipt, Bank Statement).
    \item \textbf{Speed \& Resilience:} Enforces a strict 3-second network timeout. If offline or rate-limited, the system falls back instantly ($< 5\,$ms) to a deterministic local classifier.
\end{itemize}

\section{Database and Data Export Architecture}
% -------------------------------------------------------------
To support enterprise operational workflows, the application implements structured persistence:
\begin{itemize}[leftmargin=*]
    \item \textbf{In-Memory \& Staged Storage:} Staged file uploads (\texttt{data/uploads}), rendered page bitmaps (\texttt{data/processed}), and cropped sub-documents.
    \item \textbf{Tabular CSV Export:} Full audit table including Document ID, Source File, Page Ranges, Document Type, Cluster, Centroid Distance, Extracted IDs, and Text Snippets.
    \item \textbf{Machine-Readable JSON Schema:} Hierarchical processing tree containing transition diagnostics, quality scores, cluster catalogs, and word counts.
    \item \textbf{Segmented PDF ZIP Bundle:} Automatically extracts the exact physical pages of each logical document into its own standalone PDF file using PyMuPDF and packages them into a downloadable ZIP archive.
\end{itemize}

\section{Cloud Deployment Engineering}
% -------------------------------------------------------------
The application was deployed to Streamlit Community Cloud. Key deployment engineering challenges resolved include:
\begin{enumerate}[leftmargin=*]
    \item \textbf{Native Linux OS Dependencies:} Configured \texttt{packages.txt} containing \texttt{libgl1} and \texttt{libglib2.0-0} to resolve headless OpenCV library linkages.
    \item \textbf{File Watcher Optimization:} Configured \texttt{.streamlit/config.toml} with \texttt{fileWatcherType = "none"} to prevent Streamlit from recursively scanning deep transformer packages on startup, reducing cold-start time by 10$\times$.
    \item \textbf{Cloud Secrets Integration:} Implemented automatic fallback to \texttt{st.secrets["GEMINI\_API\_KEY"]} when deployed in cloud environments.
\end{enumerate}
